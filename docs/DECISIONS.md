# 意思決定記録

## 1. 運用方法

この文書は、仕様を実装可能な形へ具体化するときの判断を記録する。各項目は次の状態を取る。

- **提案中**: Codex の推奨案。利用者の承認前であり、仕様として確定していない。
- **決定**: 利用者が承認し、`SPEC.md` と実装へ反映する。
- **置換**: 後の判断で変更された。新しい決定への参照と変更理由を残す。
- **却下**: 採用しない。再検討を避けるため理由を残す。

## 2. 実装開始前の決定

D-001〜D-008 は、2026-08-19 に利用者が提案どおり一括承認した。

### D-001 初版の範囲

- 状態: **決定**（2026-08-19）
- 推奨: 初版は旧 MATLAB 教材相当の中核、すなわち 2D/3D ベクトル、span、一次独立・一次従属、共有 URL に限定する。
- 理由: シラバス全体へ広げる前に、共通となる状態・数学・描画・共有の設計を授業で評価できる。基底以降の Lab を作り直すリスクを下げる。
- 影響: 基底、線形写像、固有値、内積等はロードマップのフェーズ 7 で個別に判断する。

### D-002 アプリの技術構成と配布方式

- 状態: **決定**（2026-08-19）
- 推奨: TypeScript、Vite、React を使用する完全クライアントサイドの静的 Web アプリとする。サーバー API、認証、データベースは初版に含めない。
- 理由: 状態に応じて複数の UI と描画を同期する用途に適し、自動テストと静的ビルドを組みやすい。学内 Web サーバーには静的ファイルだけを配置できる。
- 条件: 学内サーバーの公開パス、HTTPS、URL 書き換え可否をフェーズ 5 より前に確認する。

### D-003 描画技術

- 状態: **決定**（2026-08-19）
- 推奨: 2D は React から制御する SVG、3D は Three.js を使用する。D3 と math.js は、必要性が明確になるまで追加しない。
- 理由: 2D のベクトル、軸、ラベル、直線は SVG で十分に表現でき、DOM としてアクセシビリティも補いやすい。3D の視点操作と半透明平面は Three.js の既存機能を利用できる。依存ライブラリを必要最小限に保てる。

### D-004 ベクトルの入力方式

- 状態: **決定**（2026-08-19）
- 推奨: 数値入力と先端ドラッグの両方を同期して提供する。最初の 2D 縦断版では数値入力を先に実装し、次の作業単位でドラッグを追加する。3D の直接編集はカメラ操作との競合を試作後に判断する。
- 理由: 数値入力は授業例の正確な再現に必要で、ドラッグは変化の観察に有効である。別々の作業単位にすると、それぞれを確認しやすい。

### D-005 span と一次独立の表示

- 状態: **決定**（2026-08-19）
- 推奨: span 対象は各ベクトルのチェック操作で選ぶ。可視化に加え、日本語を主とした短い判定文、rank、span の次元を常時対応付けて表示する。面積・体積・行列式は初版の必須表示にしない。
- 理由: 色や形だけで意味を推測させず、「選択したベクトル数」と「独立な最大個数」と「span の次元」の関係を直接観察できる。行列式は正方形の場合に限られ、最初の概念説明を複雑にする。

### D-006 共有状態と URL 形式

- 状態: **決定**（2026-08-19）
- 推奨: バージョン付き JSON スキーマを定義し、Base64URL 形式の一つのクエリーパラメーターへ格納する。初版では圧縮しない。少なくとも次元、ベクトルの ID・表示名・座標、span 選択、教材上意味のある表示切替を含める。3D のカメラは、教員が意図した見え方の再現に必要かを 3D 実装時に判断する。一時的なパネル開閉、hover、ドラッグ中状態は含めない。
- 理由: スキーマを一箇所で検証でき、フィールド追加時に版を識別できる。初期段階では可読性とデバッグ容易性を圧縮より優先する。
- 未解決: 学内サーバーまたは利用サービスが許容する URL 長。

### D-007 Reset の意味

- 状態: **決定**（2026-08-19）
- 推奨: `DefaultState`、`InitialState`、`CurrentState` を区別し、Reset は共有 URL を含むページ読み込み時の `InitialState` へ戻す。アプリ既定例へ戻る操作が必要なら別名で提供する。
- 理由: 教員が配布した例を学生が操作した後、同じ授業例へ簡単に戻れる。

### D-008 対応環境とアクセシビリティの基準

- 状態: **決定**（2026-08-19）
- 推奨: 初版は現行の Chrome、Edge、Firefox、Safari の直近主要版を対象とし、PC、タブレット、スマートフォンで閲覧可能にする。操作の完全同等性は、2D ではキーボード・マウス・タッチ、3D では少なくともマウス・タッチを目標とする。色だけに依存しない識別、明示的なラベル、キーボードで変更できる数値入力、十分なタッチ領域を必須とする。
- 理由: シラバス上の教材として端末を限定しすぎず、視覚表現を利用できない状況でも数学的状態を確認できるようにする。
- 未解決: 学内で実際に管理されている端末・ブラウザの情報。

## 3. 決定後も残る確認事項

- 学内サーバーまたは利用サービスが許容する URL 長。
- 3D カメラ状態を共有 URL へ含める必要性。
- 学内で実際に管理されている端末・ブラウザの情報。
- 3D の直接編集とカメラ操作を両立できる操作方式。

これらは D-001〜D-008 を覆すものではなく、それぞれの実装フェーズで試作または運用環境を確認して具体化する。
