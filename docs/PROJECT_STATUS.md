## 作業単位 2.5 の変更

- 各ベクトルの編集欄に「spanの対象に含める」チェックを追加し、空集合を含む任意の部分集合を選択できるようにした。
- 選択集合を `X`、選択した列ベクトルを並べた行列を `B` と定義し、`rank(B)`、`dim(span(X))`、一次独立・一次従属、幾何学的な形を一つのカードで同期表示する。
- rank 0は原点の二重マーカー、rank 1は原点を通る太い破線、rank 2は座標面全体の薄い面と斜線パターンで表示する。
- パンで原点が表示外にある場合を含め、原点を通る直線と現在の表示矩形との交差区間を計算して描画する。
- 幾何表示のオン・オフを追加し、オフにしても選択集合と解析結果を維持する。既定例は2本を選択し、表示オンとした。
- 幾何表示中は未選択ベクトルを薄くし、チェック、形、線種、パターン、日本語ラベル、説明文を併用して色だけに依存しないようにした。
- 全ベクトルを列に持つ行列 `A` の一次独立・一次従属カードを別に保ち、選択集合の判定と明確に区別した。
- 既存の共有状態 v1 の `spanSelection` と `visualization.showSpan` を利用し、共有スキーマは変更していない。
- 座標面内の「生成する空間」ラベル枠を文字列長に応じた可変幅とし、「2次元座標平面全体」が枠をはみ出さないようにした。
- 選択集合の次元・形と全ベクトルのrank・判定を常時表示する要約へ分離し、要約から対応する詳細を開けるようにした。
- 3つの詳細カードを「ベクトル編集」「生成する空間」「全ベクトル」のタブへまとめ、既定では編集だけを表示するようにした。
- PCの十分な高さでは座標面をsticky表示し、タブレット以下では座標面、要約、タブ、詳細の1列配置へ切り替えるようにした。
- タブへARIA属性と左右矢印・Home・Endキー操作を追加した。選択タブは共有対象外の一時的UI状態とした。

1. 決定済み要件と受入条件は `SPEC.md` を正本とする。
2. 決定の理由、試行値、再評価条件は `docs/DECISIONS.md` を参照する。
3. 作業順と確認ゲートは `ROADMAP.md`、直近の現在地と検証結果は本書を参照する。
4. 学生向けの用語・記号は `math-writing-rules.txt` に合わせる。

文書と実装が食い違う場合は、どちらかを暗黙に正とせず差分を記録して確認する。

### 現在の状態構成

- `src/state/defaultState.ts` の `DEFAULT_2D_SHARE_STATE` がアプリ既定例で、`v₁ = (2, 1)`、`v₂ = (-3, 2)`、両方をspan対象、幾何表示オンである。
- `src/sharing/shareState.ts` の厳密な `ShareStateV1` が、次元、ベクトル、span選択、`showSpan` を保持する。`src/sharing/shareUrl.ts` がブラウザURLの構築・読込、テキスト内容・ファイル名を担当する。
- `src/app/App.tsx` は上記状態を現在の数学・共有可能状態として保持し、rankとspan解析を派生値として計算する。入力途中の文字列、手動表示範囲、ドラッグ中の表示、吸着対象、選択中の詳細タブは共有しない一時状態である。
- `src/state/appInitialization.ts` がURLなし・有効URL・不正URLをInitialStateへ変換する。Reset UIはこのInitialStateを保持し、CurrentStateと一時UIを戻す。
- `src/state/vectorCollection.ts` がD-026の追加・削除、既定座標、自動命名、span選択の同期を担当する。
- `src/teaching/twoDimensionalScenarios.ts` が5つの2D代表例と期待する数学結果を保持する。
- D-023により手動表示範囲は共有対象外とし、現行v1を維持する。復元時は自動範囲を再計算する。

## 数学用語・数式表記の確認

- `math-writing-rules.txt` を全文確認した。教科書と授業で用いる語・記号を、今後の学生向け画面の基準とする。
- `(2, 1)` のような横並び座標を列ベクトル表示へ変更した。
- 引数のない `rank` を、列ベクトルを並べた行列 `A` の `rank(A)` へ変更した。
- `span の次元` を、対象集合を明示した「生成する空間の次元」と `dim(span({...}))` の対応へ変更した。
- 「一次独立」「一次従属」は既に教科書の用語と一致している。
- 内部コードの `rank`、`spanDimension`、`spanSelection` 等は学生向け表記ではないため、意味が一致する限り変更を必須としない。

## 既知のリスクと後続確認

- D-014 の手動ズーム後の維持、「全体を表示」による自動追従への復帰、ドラッグ終了後の再調整は利用者確認済みである。D-023により手動表示は共有しない。

- D-016 の15%余白、目盛密度、入力途中の扱い、数式フォントの見た目は、利用者のブラウザ操作で問題なしと確認された。
- D-017 のホイール・ピンチ感度、倍率上下限、パン、原点が表示外にある場合の見え方は、利用者の操作確認で問題なしとされた。異なる端末で問題が出た場合は再評価する。
- D-018 の先端操作領域、ドラッグ座標の丸め、自動再フィット、手動表示維持は問題なしと確認された。
- D-019 の画面幅 `1%` の平行スナップ距離、ヒステリシスなしの操作感は利用者確認で問題なしとされた。
- D-020 のチェック配置、既定で幾何表示をオンにする方針、rank別の表現、選択集合と全ベクトルのカード分離は利用者確認で問題なしとされた。長い座標面内ラベルの枠幅は可変幅へ修正した。
- D-021 の常時要約、3タブ、画面高さ `820px` 以上でのsticky、幅 `980px`・`640px` での配置切替は利用者確認済みである。異なる実端末で問題が出た場合に再評価する。
- D-022〜D-024のクリップボード、ファイルダウンロード、フォーカス、別タブ復元、Resetは利用者確認済みである。公開先固有の制約は配布前に再確認する。
- D-025のGitHub Actionsと初回公開は利用者確認済みである。リポジトリ名またはカスタムドメインを変更する場合はbase pathを再設定する。
- D-026はデプロイ先で利用者確認済みである。
- D-027はローカル実装と自動テストまで完了し、入力案内、キーボード操作、狭い画面、5つの代表例の利用者確認を待つ。
- D-028はローカル修正と回帰テストまで完了し、iOS・Android等の実端末での再確認を待つ。
- D-009 の相対許容誤差 `1e-10` は維持する。直接操作で平行に合わせにくい問題は D-019 の操作専用スナップで解決し、数学的判定と分離する。
- D-010 の 8192 文字は防御上限であり、学内サーバー、LMS、スライド等で保証される URL 長ではない。
- GitHub Pages のプロジェクトサイトでは、ビルド時にリポジトリ名のサブパスを `APP_BASE_PATH` へ指定する必要がある。
- nginx の既定構成では一つのリクエスト行が 8 KiB を超えられないため、共有 URL の実用上限は防御上限より短くなる可能性がある。
- HTTP配信ではClipboard APIが利用できない場合があるため、HTTPSを推奨し、手動コピーとテキスト保存を代替手段として維持する。
- 3D カメラ状態を共有対象へ含めるかは 3D 実装時に判断する。
