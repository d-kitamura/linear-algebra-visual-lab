# 授業での配布・対応環境・復旧手順

最終更新: 2026-09-05

## 目的

教員が作成した2D・3D教材状態を、授業中にURLまたはQRコードで学生へ配布し、学生が同じInitialStateを開いて操作・Resetできるようにする。本書は授業直前の確認、授業中の標準手順、失敗時の代替手段を一つにまとめる。

正規の公開URL:

`https://d-kitamura.github.io/linear-algebra-visual-lab/`

## 対応環境の考え方

固定したブラウザ版番号ではなく、必要な能力と代替導線で範囲を分ける。学内管理端末の更新状況が判明した場合は、この表へ実際のOS・ブラウザを追記する。

| 段階 | 必要な能力 | 利用できる内容 | 代替 |
|---|---|---|---|
| 基本教材 | HTTPS、JavaScript、ES modules、SVG、通常のフォーム | 2D、数値入力、rank・span・一次結合、共有URL、Reset | JavaScript無効時は利用不可 |
| 3D教材 | 上記に加えてCanvasとWebGL | 右手座標系の3D幾何、視点・矢先・ターゲット操作 | 数値入力と解析カードで授業継続 |
| 自動コピー | HTTPS上のClipboard APIと利用者許可 | 「クリップボードにコピー」 | 選択済みURL欄から手動コピー |
| ファイル保存 | ブラウザのダウンロード機能 | URLの`.txt`、QRの`.png` | URL欄または画面上のQRを利用 |
| タッチ操作 | Pointer Events、`touch-action`、2点操作 | 2D/3Dのドラッグ、ピンチ、パン | 数値入力、視点プリセット |

推奨対象は、授業時点でサポート中のChrome、Edge、Firefox、Safari系ブラウザである。ただし「推奨」と「実機確認済み」は区別する。現在の確認実績は次のとおりである。

- GitHub Pages上のChromium系デスクトップで、2D/3D、共有URL、QR、Reset、不正URL、レスポンシブ表示を継続的に確認している。
- 390px相当のスマートフォン縦画面、820px相当のタブレット画面をブラウザ検証している。
- プロジェクト所有者が実機スマートフォンで、ページスクロールと2D/3D操作の分離、矢先ドラッグ、ピンチ、3D吸着、ターゲット操作を確認済みである。
- Safari、Firefox、学内管理端末の具体的な版番号、WebGL制限はまだ個別確認結果を固定していない。授業採用時の端末情報を下記チェック欄へ記録する。

## 授業前チェック欄

- [ ] 教員PCのOS・ブラウザ: ____________________
- [ ] 学内管理端末のOS・ブラウザ: ____________________
- [ ] 学生スマートフォンの確認例: ____________________
- [ ] 教室ネットワークから正規URLを開ける。
- [ ] 教室のプロジェクターへQRコードを表示し、想定する座席付近から読み取れる。
- [ ] 代表的な2D URLと3D URLを読み取り、同じベクトル・span・ターゲット・カメラになる。
- [ ] WebGLを利用できる端末では3Dが表示される。
- [ ] WebGLを利用できない場合も数値入力、解析、共有URL、Resetへ到達できる。
- [ ] URL欄の手動コピーまたはテキスト保存を、Clipboard API失敗時の代替として確認する。
- [ ] QRのPNG保存または画面表示を、ダウンロード制限時の代替として確認する。

## 教員が状態を配布する標準手順

1. 正規URLを開き、教材Labと2D/3D（線形写像では入出力の次元組）を選ぶ。0D/1Dの共有は10.7の対応まで利用できない。
2. ベクトル空間Labではベクトル・span・ターゲット、基底Labでは候補順・表示方式・ターゲット・比較基底、線形写像Labでは行列・入力・スカラーを設定する。3Dでは共有したい視点も設定する。
3. 「共有URLをエクスポート」を押す。
4. QRコードとURLが表示されたことを確認する。
5. 配布方法を選ぶ。
   - 授業中に画面のQRコードをプロジェクターへ表示する。
   - 「QRコードを保存」でPNGをスライドへ配置する。
   - 「クリップボードにコピー」でLMSや資料へ貼り付ける。
   - 「テキストで保存」でURLだけの`.txt`を保存する。
6. 教員自身の別タブまたはスマートフォンで配布URLを開き、次元、ベクトル、span、ターゲット、3Dカメラを確認する。
7. 状態を一度変更し、Resetで配布時のInitialStateへ戻ることを確認する。

手動ズーム、詳細タブ、折り畳み、ドラッグ途中の表示は共有しない。3Dカメラは共有する。共有URLを作った後で元画面を変更しても、既に生成したURLの内容は変わらない。

## 学生側の確認手順

1. QRコードを読み取るか、LMS等のURLを開く。
2. ブラウザのアドレスが正規のGitHub Pages URLであることを確認する。
3. 教員が示した次元、ベクトル本数、生成する空間または一次結合結果と一致することを確認する。
4. 指示に従ってベクトル、ターゲット、視点を操作する。
5. 初期状態へ戻すときはResetを使う。Resetはアプリ既定例ではなく、開いた共有URLの状態へ戻る。
6. ページスクロールは2D座標面・3D Canvasの外側で行う。

## 授業中の復旧手順

| 症状 | 確認 | 復旧 |
|---|---|---|
| QRを読み取れない | 投影サイズ、明るさ、ピント、距離 | LMSのURL、短い資料リンク、URL欄の表示へ切り替える |
| ページを開けない | ネットワーク、正規origin、学内フィルター | 教員PCでも確認し、テキストURLを再配布する |
| 「共有URLを開けませんでした」 | URLの欠落、複数`state`、未知版、改行 | URL全体を再コピーする。アプリは既定2D例で継続できる |
| コピーできない | Clipboard API、HTTPS、権限 | 自動選択されたURL欄から手動コピーする |
| ファイルを保存できない | 端末・ブラウザのダウンロード制限 | 画面上のQRまたはURL欄を使う |
| 3Dだけ表示できない | WebGL、GPU、コンテキスト喪失 | 数値入力・解析カード・視点説明で授業を継続する |
| ドラッグとページ操作が競合する | 操作開始位置、1点／2点操作 | 図の外でスクロールし、数値入力・視点プリセットを使う |
| 状態が教員例と違う | 古いURL、別次元、編集済み | 配布URLを開き直すかResetする |

## URL・QRの上限

- アプリが生成する完全URLは2048文字以内である。
- ベクトル空間Labの代表例16件は286〜612文字、同Labの8本・3D境界状態は1309文字である。他Labも含めた各例は共有運用テストで2048文字以内とQR生成を確認する。
- 2048文字を超える場合は、QR生成前に理由を表示する。
- 外部URL短縮サービスへ数学状態を送らない。

## 更新時の運用

- mainへのpush後、対象コミットのGitHub Actionsと公開版を確認してから授業用リンクを更新する。
- 授業直前に大量の共有URLを作り直す必要はない。D-051により正式リリース後のv3互換性を維持する。
- 変更が授業途中へ影響しないよう、授業で使用する時刻の直前には大きなデプロイを避ける。
- 問い合わせ時は、利用したURL、発生時刻、端末・OS・ブラウザ、2D/3D、表示されたメッセージを記録する。共有URLに氏名・学籍番号等の個人情報を含めない。
