採用方式: JavaScript数値を正確な2進有理数としてBigIntへ変換し、次数3以下の固有多項式・平方因子分解・Sturm列で実根数と重複度を確認する。根の値と図の座標は数値近似のまま。多重根／検出済み有理根では厳密な核を使い、単根では残差と条件を確認した近似固有ベクトルを使う。反復上限や表示数値への変換不能は保留とし、新規依存は追加しない。

参考: [SymPy多項式API（Sturm列・平方因子分解・実根区間）](https://docs.sympy.org/latest/modules/polys/reference.html)。アルゴリズムの概念を参照し、ライブラリ本体やソースの移植はしない。入力した浮動小数の正確な値に対する解析であって、利用者が意図した未入力の厳密実数を復元するものではない。

## 実装の配置と選定理由

- `src/domain/eigen.ts`: analyzeEigenMap・analyzeEigenInput、入力検証、不変スナップショット、結果の整合。
- `eigenTypes.ts`: D-103の公開型と例外。型・関数はdomain/index.tsから公開。
- `eigenExact.ts`: 内部有理数、多項式、平方因子分解、Sturmの根区間、有理固有値の核。次数3以下に限定した小さな実装とし、汎用CASは作らない。
- `eigenVectors.ts`: 根の誤差を考慮した方向精度・残差、直交基底、所属判定。React・カメラ・UI吸着とは独立。

Cardanoの公式だけ、浮動小数の判別式の閾値だけ、微小な虚部を消す方式は採用しなかった。実根・重複度を入力値に対して正確に判定する層と、画面で区別できるほど安定した固有空間かを数値で判定する層を分離できるため、本方式を採用した。依存追加・ライセンス追加・既存rank変更はない。BigIntは現在のES2022ターゲットで利用できる標準機能である。

## 数値契約（D-104）

| 項目 | 採用値・意味 |
|---|---|
| 入力 | 既存同様、有限・絶対値100万以下。微小値を事前にゼロ化しない |
| スケール | 最大絶対成分で有理数として正規化。正規化行列の根は(−4,4)内。零行列はスケール1 |
| 根区間 | 正確なSturmの根数で分割、相対幅2e-15以下で数値化。有理根を検出できた場合はその正確な値を使用 |
| 根探索の上限 | 分割の深さ192。根の精細化未完ならiteration-limit＋incomplete-spectrum。区間が0を跨ぐ微小根を0と決めない |
| 演算量の上限 | 有理数の分子・分母の合計32768 bit。超過はprecision-limitで数値計算失敗にする |
| 根・空間の残差 | 相対1e-12以下。これだけで重複度・根の個数を決めない |
| 近似方向の誤差 | 根区間の半幅と丸め誤差を余因子ベクトルへ伝播し、正規化後の方向誤差指標1e-11以下を要求 |
| 基底の識別 | 独立成分・余因子の指標1e-8以上。異なる固有空間の直和も検査し、ほぼ一致する方向は空間を保留 |
| 入力の所属 | 相対距離と等式残差が共に1e-10以下なら所属、距離1e-8以上なら不所属、中間帯は保留 |
| 零入力 | 全成分が厳密に0の場合のみ。零入力の固有ベクトル判定は常にzero-input |

有理固有値ではRREFを厳密な非零ピボットで行い、核の独立性・次元を確定する。核の基底は有理数の段階で直交化してから数値へ変換し、数値段階でも再直交化・正規化する。非有理根は次数3以下では単根なので固有空間次元は1と分かるが、図に渡すベクトルは方向精度・残差を満たす場合だけ返す。基底の最大絶対成分を正とする符号規則で再現性を保つ。

入力判定は行列の解析結果を再利用する。選択空間外でも他の固有空間に属すればeigenvector。異なる根に同時に属すように見える非零入力は保留。全根・全空間が確認できなければ、どの空間にも属さないという全体否定を出さない。

## 境界での結果

- `[[1,1],[-1e-24,1]]`: 実固有値なし。小さい虚部を0にしない。
- `[[1,1],[1e-24,1]]`: 相異なる実根2個・各重複度1は分かるが、固有直線がほぼ重なるため空間はnull・inconclusive。
- `diag(1,1+1e-12)`: 近い根でも直線が区別できるので2個のまま解析可能。表示丸めによる重根への統合は行わない。
- 三角行列の対角成分は正確な根として使用し、1e-300やNumber.MIN_VALUEを無条件に0にしない。
- `diag(1e-200,2e-200)`: 根を返せても固有多項式の非零定数項をnumberへ変換できないため、係数はnull・inconclusive。偽の零多項式を返さない。
- 3次式に極端に小さい根があるときは分割上限で止まり得る。確認済み根だけ返し、spectrumComplete=falseとする。任意の有効入力で必ずreadyになるという保証ではない。
- 入力の像で非零の積がunderflowする場合はimageVector=null・numerical-failure。理由コードunrepresentable-resultを追加し、零への写像と取り違えない。

数学上の厳密性は、入力されたbinary64値に対しての根数・重複度等の内部処理に限る。導出値や図は数値基準での確認であり、入力前の意図や任意精度の厳密表示を保証するものではない。小さな入力変更で重根が分裂すること自体は正しい挙動として扱う。
