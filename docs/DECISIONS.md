# 意思決定記録

## 1. 運用方法

この文書は、仕様を実装可能な形へ具体化するときの判断を記録する。各項目は次の状態を取る。

- **提案中**: Codex の推奨案。利用者の承認前であり、仕様として確定していない。
- **試行採用**: 小さな実装とテストで評価する初期値。利用者の確認や授業上の評価で変更できる。
- **運用候補**: 利用者が想定している運用方式。環境情報を確認して最終決定する。
- **決定**: 利用者が承認し、`SPEC.md` と実装へ反映する。
- **置換**: 後の判断で変更された。新しい決定への参照と変更理由を残す。
- **却下**: 採用しない。再検討を避けるため理由を残す。

## 2. 実装開始前の決定

### D-001 初版の範囲

- 状態: **決定**（2026-08-19）
- 推奨: 初版は旧 MATLAB 教材相当の中核、すなわち 2D/3D ベクトル、span、一次独立・一次従属、共有 URL に限定する。
- 理由: シラバス全体へ広げる前に、共通となる状態・数学・描画・共有の設計を授業で評価できる。基底以降の Lab を作り直すリスクを下げる。
- 影響: 基底、線形写像、固有値、内積等はロードマップのフェーズ 7 で個別に判断する。

### D-002 アプリの技術構成と配布方式

- 状態: **決定**（2026-08-19）
- 推奨: TypeScript、Vite、React を使用する完全クライアントサイドの静的 Web アプリとする。サーバー API、認証、データベースは初版に含めない。
- 理由: 状態に応じて複数の UI と描画を同期する用途に適し、自動テストと静的ビルドを組みやすい。学内 Web サーバーには静的ファイルだけを配置できる。
- 条件: 学内サーバーの公開パス、HTTPS、URL 書き換え可否をフェーズ 5 より前に確認する。

### D-003 描画技術

- 状態: **決定**（2026-08-19）
- 推奨: 2D は React から制御する SVG、3D は Three.js を使用する。D3 と math.js は、必要性が明確になるまで追加しない。
- 理由: 2D のベクトル、軸、ラベル、直線は SVG で十分に表現でき、DOM としてアクセシビリティも補いやすい。3D の視点操作と半透明平面は Three.js の既存機能を利用できる。依存ライブラリを必要最小限に保てる。

### D-004 ベクトルの入力方式

- 状態: **決定**（2026-08-19）
- 推奨: 数値入力と先端ドラッグの両方を同期して提供する。最初の 2D 縦断版では数値入力を先に実装し、次の作業単位でドラッグを追加する。3D の直接編集はカメラ操作との競合を試作後に判断する。
- 理由: 数値入力は授業例の正確な再現に必要で、ドラッグは変化の観察に有効である。別々の作業単位にすると、それぞれを確認しやすい。

### D-005 span と一次独立の表示

- 状態: **決定**（2026-08-19）
- 推奨: span 対象は各ベクトルのチェック操作で選ぶ。可視化に加え、日本語を主とした短い判定文、rank、span の次元を常時対応付けて表示する。面積・体積・行列式は初版の必須表示にしない。
- 理由: 色や形だけで意味を推測させず、「選択したベクトル数」と「独立な最大個数」と「span の次元」の関係を直接観察できる。行列式は正方形の場合に限られ、最初の概念説明を複雑にする。

### D-006 共有状態と URL 形式

- 状態: **決定**（2026-08-19）
- 推奨: バージョン付き JSON スキーマを定義し、Base64URL 形式の一つのクエリーパラメーターへ格納する。初版では圧縮しない。少なくとも次元、ベクトルの ID・表示名・座標、span 選択、教材上意味のある表示切替を含める。3D のカメラは、教員が意図した見え方の再現に必要かを 3D 実装時に判断する。一時的なパネル開閉、hover、ドラッグ中状態は含めない。
- 理由: スキーマを一箇所で検証でき、フィールド追加時に版を識別できる。初期段階では可読性とデバッグ容易性を圧縮より優先する。
- 未解決: 学内サーバーまたは利用サービスが許容する URL 長。

### D-007 Reset の意味

- 状態: **決定**（2026-08-19）
- 推奨: `DefaultState`、`InitialState`、`CurrentState` を区別し、Reset は共有 URL を含むページ読み込み時の `InitialState` へ戻す。アプリ既定例へ戻る操作が必要なら別名で提供する。
- 理由: 教員が配布した例を学生が操作した後、同じ授業例へ簡単に戻れる。

### D-008 対応環境とアクセシビリティの基準

- 状態: **決定**（2026-08-19）
- 推奨: 初版は現行の Chrome、Edge、Firefox、Safari の直近主要版を対象とし、PC、タブレット、スマートフォンで閲覧可能にする。操作の完全同等性は、2D ではキーボード・マウス・タッチ、3D では少なくともマウス・タッチを目標とする。色だけに依存しない識別、明示的なラベル、キーボードで変更できる数値入力、十分なタッチ領域を必須とする。
- 理由: シラバス上の教材として端末を限定しすぎず、視覚表現を利用できない状況でも数学的状態を確認できるようにする。
- 未解決: 学内で実際に管理されている端末・ブラウザの情報。

### D-009 rank 判定の数値方針

- 状態: **試行採用・利用者確認済み**（2026-08-19、作業単位 1.2）
- 方針: 初版の内部計算は JavaScript の有限な倍精度浮動小数点数を使用する。各ベクトルを最大絶対座標で個別に正規化した後、部分ピボット付き消去法で rank を求める。
- 許容誤差: 既定の相対許容誤差は `1e-10` とし、数学ロジックの呼び出し時に変更可能にする。
- 意味: ベクトルの単純な定数倍で判定が変わりにくく、正規化後のピボットが許容誤差以下なら、教材上はほぼ一次従属として扱う。
- 規約: 空集合は rank 0、span の次元 0、一次独立とする。0 ベクトルを一つでも単独で含む集合は一次従属となる。
- 保留: 有理数・無理数の厳密計算と `1/3`、`√2` 等の表示は初版の rank 判定に含めず、教材上の必要性を確認して別途判断する。
- 操作確認結果: 2D の直接操作後も `1e-10` を維持する。ドラッグだけで完全な平行へ合わせにくい問題は、数学的判定閾値を緩めず D-019 の操作専用スナップで解決した。許容誤差付近を学生へどう説明するかは引き続き教材設計上の確認事項とする。

### D-010 共有状態 v1 のスキーマと安全上限

- 状態: **試行採用・利用者確認済み**（2026-08-19、作業単位 1.3）
- スキーマ: `v`、`lab`、`dim`、`vectors`、`spanSelection`、`visualization.showSpan` だけを受け付ける。未知のフィールドは暗黙に保持せず拒否する。
- エンコード: 検証・正規化した状態を UTF-8 JSON に変換し、パディングなしの Base64URL とする。圧縮は行わない。
- デコード: Base64URL、UTF-8、JSON、スキーマの順に検証し、例外を外へ漏らさず成功または分類済みエラーを返す。
- 安全上限: ベクトル 8 本、ID 32 文字、表示名 40 文字、座標絶対値 `1,000,000`、エンコード文字列 8192 文字とする。
- 理由: 初版の授業例には十分な余裕を持たせつつ、改変 URL による過大なメモリ・描画負荷を早期に拒否できる。状態を正規化することで同じ状態から決定的な文字列を生成できる。
- 注意: 8192 文字はアプリの防御上限であり、学内サーバー、LMS、スライド等で利用可能な URL 長を保証する値ではない。
- 再評価条件: 2D の実例を共有 URL にして、対象ブラウザ、教材スライド、LMS 等で往復確認した後に上限と圧縮の必要性を再確認する。

### D-011 公開方式

- 状態: **運用候補**（2026-08-19）
- 候補: GitHub Pages のプロジェクトサイト、または学内 Web サーバー上の nginx で静的成果物を配信する。
- 共通方針: サーバー API を必要としない静的アプリを維持し、共有状態は同じページのクエリーパラメーターで表現する。公開先のサブパスを前提に、アセットとアプリ内リンクをベースパス対応にする。
- GitHub Pages: 通常のプロジェクトサイトは `/<repositoryname>/` 以下で公開されるため、Vite の `base` を公開パスに合わせる必要がある。GitHub Actions によるビルドと `dist/` の公開を候補とする。
- nginx: ルートまたはサブパスのどちらで配信するかを確認する。将来クライアント側ルーティングを導入する場合は、`try_files` 等による `index.html` へのフォールバックが必要になる。
- URL 長: nginx の既定構成では大きなリクエストヘッダーバッファが 8 KiB で、リクエスト行は一つのバッファを超えられない。D-010 の 8192 文字は状態文字列だけの防御上限なので、完全な URL としてそのまま通る保証はない。
- 最終決定時に必要な情報: 公開 URL、ルートかサブパスか、HTTPS、GitHub Pages のカスタムドメイン有無、nginx 設定を変更できる権限、学内ネットワーク外からの利用可否。

- 表示範囲: x 軸・y 軸ともに `-5` から `5` までの正方形とし、整数単位の目盛線を表示する。

### D-013 2D 表示範囲の自動・手動操作

- 状態: **決定**（2026-08-19）
- 自動操作: ベクトルを操作・編集して現在の表示範囲を超える場合を含め、原則としてベクトルが見える範囲へ自動的にスケーリングする。
- 手動操作: PC では少なくともマウスホイール、タッチ端末では少なくともピンチ操作により、利用者が表示範囲を拡大・縮小できるようにする。
- 補助操作: ホイールやピンチを使えない利用者のため、キーボードで操作できる拡大、縮小、「全体を表示」の画面ボタンを併設する。
- 理由: 数値入力可能範囲と可視範囲を固定値 `[-5, 5]` に結び付けず、大小の異なる例を同じ教材画面で観察できるようにする。
- 具体化: 自動追従と手動操作の切替、倍率の上下限、ズーム感度、パンは D-014・D-017 で試行採用し、利用者確認済みである。共有時は D-023 により手動表示範囲を含めず、復元時に自動範囲を再計算する。

### D-014 自動追従モードと表示範囲の共有

- 状態: **試行採用・利用者確認済み**（2026-08-19）
- モード: 初期状態は自動追従とし、全ベクトルの終点と原点が余白付きで収まる正方形範囲を計算する。`[-5, 5] × [-5, 5]` を自動追従時の最小範囲とする。
- 手動優先: ホイール、ピンチ、パン、拡大・縮小ボタンを使った後は手動表示を維持し、その後のベクトル編集で表示範囲を勝手に変更しない。「全体を表示」で自動追従へ戻す。
- ドラッグ中: 自動追従モードでも、先端ドラッグ中は座標変換を安定させるため表示範囲を固定し、操作終了後に再計算する。
- 共有: 当初は手動表示の中心と倍率を共有候補としたが、D-023 により共有対象外へ変更した。復元時はベクトルから自動表示範囲を再計算する。
- スキーマ: 表示範囲を追加しないため、現行の厳密な共有状態 v1 を維持する。
- 理由: 自動追従が手動操作を打ち消すことと、ドラッグ中の表示倍率変化による操作の不安定化を避けつつ、共有 URL の再現性を保つ。
- 再評価条件: 数値入力、手動ズーム、パン、先端ドラッグを実際に操作し、自動追従との切替や共有時の再現が授業用途に適するかを確認する。

### D-015 教材内の数学用語・数式表記

- 状態: **試行採用・利用者確認済み**（2026-08-19、利用者提示）
- 基準文書: リポジトリ直下の `math-writing-rules.txt` を、学生向け画面・説明・例題で使用する数学用語と数式表記の基準とする。利用者による追記・修正を反映できる生きた文書として扱う。
- 適用範囲: 画面に表示する数式、ラベル、説明文、アクセシブルな読み上げ文、授業用例を対象とする。TypeScript の型名、プロパティ名、テスト名等の内部識別子は対象外とする。
- フェーズ 2 の主要規則: 数ベクトルは列ベクトルとする。ベクトル記号は基本文字だけをボールド斜体小文字とし、添え字の数字は立体レギュラーとする。一次結合・一次関係・一次独立・一次従属は「一次」を優先する。「ベクトルが生成する空間」を主表現とし、`span` と「張る空間」を対応する補助語として示す。
- `rank` と `dim`: `rank` は列ベクトルを並べた行列または写像を引数として明示し、`dim` はベクトル空間を引数として明示する。例えば `A = [v₁ v₂]` を定義して `dim(span({v₁, v₂})) = rank(A)` の対応を示す。
- 集合と組: 順序に依存しない対象は集合、基底や列の順序を扱う対象は組として区別する。`span` の既定表記ではベクトル集合を波括弧で明示する。
- 描画方法: TeX 風の意味と見た目を再現するが、HTML/CSS、MathML、数式描画ライブラリのどれを採用するかは、必要な式の複雑さとアクセシビリティを確認して別途決める。生の TeX コマンドを学生向け画面へそのまま表示しない。
- 棚卸し: 各作業単位の画面確認と各フェーズ終了時に、画面文言を `math-writing-rules.txt` と照合する。

### D-016 数値入力と自動スケールの初期挙動

- 状態: **試行採用・利用者確認済み**（2026-08-19、作業単位 2.2）
- 入力形式: 10 進整数、小数、指数表記を受け付ける。空欄、入力途中、16 進表記、非有限値は確定済みの数学状態へ反映しない。
- 入力上限: 共有状態と同じく各成分の絶対値を `1,000,000` 以下とする。`-0` は `0` に正規化する。
- 入力途中: 入力欄の文字列と `CurrentState` の数値を分離し、不正な文字列を画面に残して訂正可能にしながら、描画と判定には直前の有効値を用いる。
- 自動範囲: 原点中心の正方形とし、`[-5, 5] × [-5, 5]` を最小範囲とする。最大絶対成分に 15% の余白を加えて全ベクトルを収める。
- 目盛: 表示幅を約 10 区間に分けることを目標に、`1`、`2`、`5` と 10 の累乗から目盛間隔を選ぶ。大きい値は指数表記にする。
- 数式表示: OS が提供する `Cambria Math` 等の数式用フォントを優先する。ベクトルの基本文字と行列をボールド斜体、ベクトルの添え字数字と `rank`、`dim`、`span` を立体レギュラーで表示する。現段階では外部数式描画ライブラリを追加しない。
- 再評価条件: 小数・指数表記・上限付近の入力、自動倍率の変化、画面幅の違いを操作し、余白、目盛密度、入力確定方式、数式の見た目を確認する。

### D-017 2D 手動表示操作の初期値

- 状態: **試行採用・利用者確認済み**（2026-08-19、作業単位 2.3）
- モード: ページ読み込みと「全体を表示」後は自動追従、ホイール、ピンチ、パン、拡大・縮小ボタンの使用後は手動表示とする。手動表示中の数値編集では表示範囲を維持する。
- ズーム中心: ホイールはポインター位置、ピンチは2点の中点を数学座標上の固定点として倍率を変える。画面ボタンは現在の表示中心を基準にする。
- 画面ボタン: 拡大は表示幅を `0.8` 倍、縮小は `1.25` 倍とする。ネイティブなボタンとしてキーボード操作とフォーカス表示を提供する。
- ホイール感度: 1イベントの係数を `exp(deltaY × 0.0015)` とし、極端なイベント値は計算前に抑える。
- パン: 座標面の背景をドラッグした距離に対応して表示中心を移す。ベクトル自体は作業単位 2.4 までポインター操作の対象にしない。
- 安全範囲: 正方形表示の半幅を `0.1` 以上 `2,000,000` 以下、中心座標の絶対値を `2,000,000` 以下に制限する。
- 範囲外表示: パンまたはズームにより原点やベクトルが表示外へ出ることを許可し、描画を座標面内へクリップする。「全体を表示」で復帰できる。
- 再評価条件: マウスホイール、トラックパッド、ピンチ、背景ドラッグ、画面ボタンを実機で操作し、感度、上下限、スクロール競合、軸・目盛の視認性を確認する。

### D-018 2D ベクトル先端ドラッグの初期挙動

- 状態: **試行採用・利用者確認済み**（2026-08-19、作業単位 2.4。平行操作の課題は D-019 で解決）
- 入力手段: マウス、ペン、タッチを Pointer Events で統一して扱う。キーボードでは既存の数値入力欄を同じ数学状態への代替操作とする。
- 操作領域: 見た目の先端点とは別に、半径 `18` の透明な SVG 操作領域を設ける。hover またはドラッグ中はベクトル色の薄い円で対象を示す。
- ジェスチャー分離: 先端の操作領域はベクトル編集専用、座標面の背景はパン・ピンチ専用とし、どちらかの操作中にもう一方を開始しない。先端ドラッグ中のホイールズームも抑止する。
- 表示範囲: 自動表示ではドラッグ開始時の範囲を終了まで固定して終了後に再計算する。手動表示では編集前後の範囲を維持する。
- 座標値: グリッドへのスナップは行わない。表示上の1ピクセルに相当する数学座標を基準に10の累乗の丸め幅を選び、数値入力欄が不要に長い小数にならないようにする。
- 安全上限: 数値入力および共有状態と同じく各成分の絶対値を `1,000,000` 以下に制限し、`-0` を `0` に正規化する。
- 再評価条件: マウスとタッチ相当の操作で、先端のつかみやすさ、丸め幅、自動再フィット、手動表示の維持、ほぼ平行な位置での D-009 の判定変化を確認する。

利用者の操作確認では全体として問題なかったが、D-009 の `1e-10` にドラッグだけで座標を合わせ、一次従属へ変化させることは難しかった。数学的な判定閾値を緩めず、D-019 の操作補助を追加する。

### D-019 ドラッグ中の平行スナップ

- 状態: **試行採用・利用者確認済み**（2026-08-19、作業単位 2.4）
- 適用範囲: ベクトル先端のドラッグ中だけに適用する。数値入力には適用せず、入力値を暗黙に変更しない。
- 操作閾値: ドラッグ中のベクトル `v` の先端と、他の非零ベクトル `w` が張る直線との垂直距離 `|det(v, w)| / ||w||` を用いる。基準表示範囲 `[−5, 5] × [−5, 5]` では距離 `0.1`、一般には現在の表示幅の `1%` 以下で吸着する。表示幅100では `1`、表示幅4では `0.04` となり、画面上の吸着幅を一定に保つ。
- 吸着位置: 閾値内に複数の候補がある場合は画面上の垂直距離が最も近いベクトルを選び、そのベクトルが張る直線へ先端を直交射影する。同方向と反対方向の両方を対象とする。
- 零ベクトル: ドラッグ中のベクトルが零ベクトルの場合は吸着しない。零ベクトルは方向を持たないため、吸着先からも除外する。
- 視覚表示: 吸着中はドラッグ先端の操作円を強調し、吸着先ベクトルを太い破線で表示する。
- 安全上限: 射影後に座標上限を超える場合は、平行関係を壊さないよう両成分を同じ倍率で縮小する。
- D-009 との分離: rank 判定の相対許容誤差 `1e-10` は変更しない。スナップ後の座標を完全な平行として `CurrentState` へ反映し、その状態を通常の D-009 で判定する。
- ヒステリシス: 現時点では不要との利用者判断により、吸着開始と解除に同じ距離を用いる。
- 再評価条件: 基準範囲、拡大表示、縮小表示で画面上の吸着幅が同程度に感じられるか、吸着時の跳び、境界から外れるときの安定性、視覚表示を実際に操作して確認する。

利用者の操作確認では、画面幅 `1%` の吸着距離、表示倍率に対する相対性、ヒステリシスなしの操作感に問題はなかった。

### D-020 2Dで生成する空間を選択・表示する初期方式

- 状態: **試行採用・利用者確認済み**（2026-08-19、作業単位 2.5）
- 選択操作: 各ベクトルの編集欄にネイティブなチェックボックスを設け、マウス、タッチ、キーボードで `spanSelection` を変更する。選択順ではなく画面のベクトル順で集合を表示する。
- 空集合: 全ベクトルのチェックを外すことを許可する。空集合は rank 0、一次独立であり、生成する空間は原点だけからなる零部分空間とする。
- 幾何表示: rank 0 は原点の二重マーカー、rank 1 は原点を通る太い破線、rank 2 は座標面全体の薄い面と斜線パターンで表す。座標面内の日本語ラベルとカード内の説明を併用する。
- 選択の識別: 幾何表示中は `spanSelection` に含まれない矢印の不透明度を下げる。選択チェック、線種、パターン、ラベルを併用し、色だけに依存しない。
- 表示切替: `visualization.showSpan` は幾何表示だけをオン・オフし、選択集合と解析結果は維持する。既定例では2本を選択し、幾何表示をオンにする。

- 状態共有: 既存の共有状態 v1 にある `spanSelection` と `visualization.showSpan` をそのまま用いるため、スキーマ変更は行わない。
- 再評価条件: 空集合、1本、平行な2本、一次独立な2本を切り替え、選択操作、初期表示、幾何表現、説明の分かりやすさを確認する。

利用者の操作確認では基本的な表示と操作に問題はなかった。「2次元座標平面全体」の座標面内ラベルが固定枠をはみ出したため、文字列長に応じた可変幅へ修正した。

### D-024 共有URLの読込、エラー、InitialState、Reset

- 状態: **決定・実装済み、利用者操作確認待ち**（2026-08-19、作業単位2.6）
- URL形式: 現在のoriginと公開サブパスを維持し、クエリーパラメーター名を `state` とする。エクスポートURLから既存クエリーとハッシュを除き、状態を1件だけ格納する。エクスポートしても閲覧中ページのURLとブラウザ履歴は変更しない。
- 通常起動: `state` がなければ `DefaultState` を `InitialState` とする。
- 共有起動: 有効な2D v1なら復元結果を `InitialState` とし、その後通常どおり編集できる。
- 不正URL: 空、重複、壊れた状態、未対応版、2D画面での3D状態は安全に拒否する。アプリは停止せず `DefaultState` を `InitialState` として表示し、復元できなかった理由を閉じられる案内で示す。
- Reset: `CurrentState` を `InitialState` へ戻し、入力欄の文字列を同期し、表示を自動範囲、詳細タブを「ベクトル編集」へ戻し、ドラッグ・吸着・エクスポートの一時状態を消去する。閲覧中URLは変更しない。
- 配布: GitHub Pages等のサブパスを維持する。クリップボードの安定利用にはHTTPSを推奨し、HTTP環境では手動コピーとテキスト保存を代替手段とする。
